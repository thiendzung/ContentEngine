## Architecture decisions

1. No new migration/table for checkpoint or budget in PR-B.
2. Checkpoint is a versioned `Artifact` with `artifact_type=checkpoint`.
3. Approval uses existing durable `Approval` records and always points to one exact artifact ID/version.
4. A newer artifact of the same run/type makes an older artifact ineligible for a new approval decision; old approval history is preserved.
5. Human rejection cancels the run and is not a machine retry.
6. Retry policy is resolved data passed to runtime; workflow code does not hide retry counts.
7. A retry creates a new `StepRun` attempt and a new durable `Job`; the failed attempt remains immutable history.
8. Worker failure + retry scheduling happen in one caller-owned DB transaction.
9. Existing `ModelCall` and `ToolCall` ledgers are the source for count/token/cost usage. Context estimate, research source count and revise-loop count remain explicit runtime counters until later phases add dedicated ledgers.
10. Budget stop returns explicit exceeded-limit reasons.

## Required invariants

- checkpoint never overwrites an older checkpoint;
- approval pause is durable;
- stale artifact cannot receive current approval;
- stale lease owner cannot create retry;
- retry is bounded;
- non-retryable errors stop clearly;
- budget cannot fail silently;
- PR-A queue/lease invariants remain green.
