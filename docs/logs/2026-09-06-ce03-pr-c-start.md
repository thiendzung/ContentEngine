## Architecture decisions

1. PR-C reuses CE02 persistence; do not create a second settings, manifest or telemetry store.
2. `ModelRouter` resolves a task using the immutable `SettingsSnapshot`; business workflow never hardcodes provider/model names.
3. `ModelClient` execution stays behind a provider-neutral request/response contract.
4. `ToolAdapter` exposes one provider-neutral tool execution seam; research/business modules own tool meaning, Harness owns durable execution records.
5. Every important model call must reference a persisted `ContextManifest` before generation.
6. ContextManifest records exact settings snapshot, prompt/recipe version, evidence/knowledge/golden/tool references needed to explain what the model saw.
7. `ModelCall` and `ToolCall` tables created in CE02 remain the telemetry source of truth.
8. Telemetry records start/completion/failure, tokens/cost/latency/result refs/error class without storing secrets.
9. Budget enforcement from PR-B reads these same ledgers; PR-C must not add hidden counters for model/tool usage.
10. No real external provider is required to prove PR-C contracts. Deterministic fake adapters are preferred in tests; real provider wiring belongs in later production modules.

## Target runtime flow

```text
StepRun
↓
resolve SettingsSnapshot
↓
ModelRouter.resolve(task_key, project, locale, settings)
↓
build + persist ContextManifest
↓
start ModelCall telemetry
↓
ModelClient.generate(request)
↓
complete/fail ModelCall telemetry
↓
persist result Artifact
```

Tool path:

```text
StepRun
↓
ToolAdapter.execute(tool request)
↓
start ToolCall telemetry
↓
normalized result / error
↓
persist result ref + latency + error class
```

## Required invariants

- no hardcoded provider/model in workflow business logic;
- important model call cannot run without ContextManifest reference;
- manifest is immutable after creation;
- manifest hash is deterministic for the same bounded context refs;
- ModelCall references exact manifest + step/run;
- ToolCall keeps stable request fingerprint;
- telemetry failure preserves error class;
- retry/budget logic from PR-B remains compatible;
- no secret is written into manifest or telemetry payloads.

## Exit gate

