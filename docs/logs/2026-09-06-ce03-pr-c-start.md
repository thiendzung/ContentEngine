## Architecture decisions

1. PR-C reuses CE02 persistence; do not create a second settings, manifest or telemetry store.
2. `ModelRouter` resolves a task using the immutable `SettingsSnapshot`; business workflow never hardcodes provider/model names.
3. `ModelClient` execution stays behind a provider-neutral request/response contract.
4. `ToolAdapter` exposes one provider-neutral tool execution seam; research/business modules own tool meaning, Harness owns durable execution records.
5. Every important model call must reference a persisted `ContextManifest` before generation.
6. `ModelCall` and `ToolCall` tables created in CE02 remain the telemetry source of truth.
7. Telemetry records start/completion/failure, tokens/cost/latency/result refs/error class without storing secrets.
8. Budget enforcement from PR-B reads these same ledgers; PR-C must not add hidden counters for model/tool usage.
9. No real external provider is required to prove PR-C contracts. Deterministic fake adapters are preferred in tests; real provider wiring belongs later.
10. Tool request fingerprint includes both `tool_key` and normalized payload.
11. `ModelCall.prompt_version` must match its exact `ContextManifest.prompt_version`.
12. A model result Artifact must belong to the same run + step as its ModelCall.

## Contract reconciliation

`docs/04-SETTINGS-CONTRACT.md` already requires ContextManifest to preserve the `OriginalityPack` used by the model. The CE02 database model and the ContextManifest list in `docs/03-DATA-CONTRACT.md` did not preserve this reference.

PR-C therefore adds nullable `ContextManifest.originality_pack_id` through migration `20260906_0008`.

Do not hide this reference in `tool_result_refs` or another unrelated field. `docs/03-DATA-CONTRACT.md` must be updated in the same PR before merge.

## Target runtime flow

```text
StepRun
↓
resolve SettingsSnapshot
↓
ModelRouter.resolve(task_key, settings)
↓
build + persist ContextManifest
↓
start ModelCall telemetry
↓
ModelClient.generate(request)
↓
complete/fail ModelCall telemetry
↓
persist result Artifact
```

Tool path:

```text
StepRun
↓
start ToolCall telemetry
↓
ToolAdapter.execute(tool request)
↓
normalized result / error
↓
complete/fail ToolCall telemetry
```

## Required invariants

- no hardcoded provider/model in workflow business logic;
- important model call cannot run without ContextManifest reference;
- manifest is immutable after creation;
- manifest hash is deterministic for the same bounded context refs;
- manifest records SettingsSnapshot, prompt/recipe, EvidenceSet, OriginalityPack and bounded refs;
- EvidenceSet/OriginalityPack cannot silently cross ContentCase boundaries;
- ModelCall references exact manifest + step/run and matching prompt version;
- model result Artifact matches ModelCall run + step;
- ToolCall keeps stable request fingerprint including tool identity;
- telemetry failure preserves error class;
- retry/budget logic from PR-B remains compatible;
- no secret is written into manifest or telemetry payloads.
