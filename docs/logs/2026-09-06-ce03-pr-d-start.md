## Architecture decisions

1. Database remains the source of truth for side-effect intent.
2. External side effects are never executed before the durable intent is committed.
3. Every outbox item has a stable idempotency key and explicit lifecycle.
4. A worker crash after an external service accepted a request but before local persistence is treated as ambiguous, not as automatic failure.
5. Ambiguous outcomes must reconcile before any resend.
6. Reconciliation adapters return a normalized result: confirmed success, confirmed absent, conflict, or still unknown.
7. Duplicate prevention is proven by tests around the outbox/idempotency boundary, not by trusting provider behavior.
8. Restart/resume must load durable run/checkpoint/job/outbox state and continue without repeating confirmed side effects.
9. This PR does not implement WordPress publishing itself. Use a deterministic fake side-effect adapter in tests.
10. Replay/eval stays out of PR-D because it has different semantics: frozen inputs, no publish, candidate-vs-baseline comparison.

## Target side-effect flow

```text
step decides side effect
→ persist OutboxIntent + idempotency key
→ commit database transaction
→ worker claims intent
→ call external adapter
→ persist confirmed external result
→ mark intent complete
```

Crash ambiguity:

```text
external system may have accepted request
→ worker crashes before local success record
→ lease/attempt resumes
→ reconcile(idempotency key / external locator)
├── confirmed success → persist result, do not resend
├── confirmed absent → safe to retry/send
├── conflict → stop with explicit conflict
└── unknown → keep pending/reconciliation state, do not blind resend
```

## Required invariants

- no external side effect before durable intent commit;
- idempotency key is stable for one logical side effect;
- completed intent cannot be executed again;
- ambiguous intent reconciles before retry;
- confirmed external success is persisted exactly once locally;
- restart does not reset completed side-effect state;
- duplicate side-effect test proves one logical action results in at most one confirmed external action;
- lease/retry/checkpoint invariants from PR-A/PR-B remain green.

## Exit gate

PR-D passes only when one synthetic workflow proves:

```text
create run
→ persist side-effect intent
→ simulate external accept
→ simulate worker crash before local success write
→ restart/resume
→ reconciliation finds accepted external result
→ local result persisted
→ intent completed
→ retry/restart again
→ no second external action
```

Also prove:

- confirmed absent can safely retry;
- conflict stops explicitly;
- unknown does not blind retry;
- full CE03 regression remains green.
