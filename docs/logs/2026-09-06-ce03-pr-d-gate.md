## Architecture result

PR-D keeps PostgreSQL as the source of truth for external side-effect intent.

The worker protocol is:

```text
persist OutboxIntent
→ commit
→ claim durable Job lease
→ mark intent processing
→ commit processing state
→ call external adapter outside DB transaction
→ persist confirmed result
```

If a worker dies after an external system may have accepted the request but before local success is written:

```text
processing survives restart
→ new worker reclaims expired Job lease
→ reconcile before resend
```

Reconciliation outcomes are normalized:

- `confirmed_success` → complete locally, do not resend;
- `confirmed_absent` → return to pending, safe to retry;
- `conflict` → fail explicitly with `publish_conflict`;
- `unknown` → remain `needs_reconciliation`, no blind retry.

The existing Job lease remains the only execution lease. PR-D does not introduce a second lease system.

## Proven invariants

- same idempotency key + same logical intent reuses the same OutboxIntent;
- same idempotency key + different payload/run/type is rejected;
- only current valid Job lease owner may dispatch, complete or apply reconciliation;
- stale worker cannot write success after lease reclaim;
- `processing` and `needs_reconciliation` cannot dispatch blindly;
- completed intent cannot dispatch again even while the current worker still owns a valid lease;
- completed Job independently blocks later execution because no valid lease remains;
- confirmed external success is persisted with the exact external reference;
- restart/resume preserves completed side-effect state;
- integration test commits `processing` in one session before the fake network call, then opens new sessions to prove restart/reconciliation;
- fake external adapter execute count remains exactly `1` across crash + restart + reconciliation;
- SettingsSnapshot immutability remains intact; tests do not delete or mutate it.
