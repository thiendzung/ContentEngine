## Goal

Productionize the CE01 research provider spike into a bounded `ResearchRouter` that:

1. checks internal MOTGU knowledge before broad external search;
2. uses CE03 budget and ToolCall telemetry rather than a parallel harness;
3. calls Serper first for Google discovery when external research is needed;
4. calls Tavily or Exa only when the prior result is insufficient for the request;
5. uses Jina only to read selected URLs;
6. records provider decisions, provenance and stop reason;
7. never treats search rank/provider score as factual authority;
8. never converts Discovery output directly into Evidence.

## Locked provider roles

```text
Internal knowledge first
↓
Serper — Google discovery
↓ if insufficient
Tavily — better source discovery when SERP is weak/noisy
OR
Exa — semantic / deeper / second-hop discovery
↓
Jina — read selected URL only
```

Brave remains optional. Default PR-C decision is **do not implement** unless a real-run gate proves a concrete coverage/outage need.

- internal knowledge sufficient → zero external provider calls;
- Serper sufficient → no Tavily/Exa;

## Implementation findings

### Reuse CE03 instead of creating a second harness

Production research uses the existing CE03 primitives:

```text
BudgetLimits
+ load_budget_usage
+ ToolCall telemetry
```

There is no second durable provider-call counter or research-specific queue.

One provider invocation is one logical CE03 `ToolCall`. Serper may perform its own bounded search/autocomplete sub-calls internally; those remain visible as `ProviderCallArtifact` details instead of becoming a second durable ledger.

### Failure classes

Provider failures are normalized into the existing harness classes:

```text
401/403 -> provider_auth
429     -> provider_rate_limit
5xx/network/timeout -> provider_transient
invalid response -> tool_invalid_response
budget stop -> budget_exceeded
```

Error telemetry must not contain credentials or provider response bodies that may contain sensitive data.

### Sufficiency is purpose-aware

A major failure-first finding: generic discovery sufficiency cannot be reused for every research purpose.

For normal discovery:

```text
relevant questions + source coverage + at least one better source
```

can be enough.

For an explicit second-hop/source-chase request:

```text
parent_url present
→ generic Serper sufficiency is NOT enough
→ Exa second-hop candidate must preserve relation + exact parent_url
```

Internal knowledge can provide context but does not short-circuit an explicit source chase.

### Second-hop provenance must survive dedupe and selection

If the same URL appears first as a direct Serper result and later as an Exa second-hop result, dedupe keeps the stronger second-hop provenance rather than silently dropping it.

When a second-hop request reads one page, a matching second-hop candidate is selected before unrelated generic direct results so Jina reads the source relevant to the requested chase.

### Exa implementation choice

Do not add a deprecated special similarity endpoint just to make the implementation look more advanced. The production adapter keeps the current search seam and makes second-hop intent explicit through query purpose plus structured `parent_url` provenance.

The parent URL proves how the candidate was researched; it does not itself prove that the candidate is factual Evidence.

### Raw data boundary

Raw/bounded provider excerpts are research artifacts only.

They do not become:

```text
Approved Knowledge
Evidence
Obsidian content
```

without later CE04 admission/evidence workflows.
