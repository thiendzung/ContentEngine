## Goal

Productionize the CE01 research provider spike into a bounded `ResearchRouter` that:

1. checks internal MOTGU knowledge before broad external search;
2. uses CE03 budget, ToolAdapter and telemetry rather than a parallel harness;
3. calls Serper first for Google discovery when external research is needed;
4. calls Tavily or Exa only when the prior result is insufficient for the request;
5. uses Jina only to read selected URLs;
6. records provider decisions, provenance and stop reason;
7. never treats search rank/provider score as factual authority;
8. never converts Discovery output directly into Evidence.

## Locked provider roles

```text
Internal knowledge first
↓
Serper — Google discovery
↓ if insufficient
Tavily — better source discovery when SERP is weak/noisy
OR
Exa — semantic / deeper / second-hop discovery
↓
Jina — read selected URL only
```

Brave remains optional. Default PR-C decision is **do not implement** unless a real-run gate proves a concrete coverage/outage need.

## Acceptance tests

Must include:

- internal knowledge sufficient → zero external provider calls;
- Serper sufficient → no Tavily/Exa;
- Serper noisy/insufficient → one justified fallback;
- second-hop/deeper need → Exa path;
- selected URL → Jina reader;
- timeout/rate-limit/auth/invalid payload classification;
- budget exhaustion blocks further provider calls;
- duplicate result normalization;
- fallback loop prevention;
- provider decision/reason/provenance retained;
- Discovery result does not become Evidence.

## Risks

1. Hidden provider retry can bypass CE03 retry/budget.
2. Existing CE01 spike helpers may mix orchestration with adapter behavior.
3. Provider-specific scores may accidentally be treated as source authority.
4. A generic router can become over-engineered if sufficiency is not kept explicit and small.
5. Jina can be misused as a search/authority component instead of selected-page reader.
