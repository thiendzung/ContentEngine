## Implementation evidence

- `SettingsModelRouter` resolves task routes only from immutable `SettingsSnapshot` data.
- model providers are injected through `ModelClientRegistry`; workflow code does not hardcode a provider client.
- tools are injected through `ToolRegistry` and the provider-neutral `ToolAdapter` contract.
- `ContextManifest` persists the exact settings snapshot, prompt/recipe version, EvidenceSet, OriginalityPack, knowledge refs, golden example refs, and tool-result refs used for an important model call.
- migration `20260906_0008` adds nullable `originality_pack_id` to `context_manifests` with a foreign key to `originality_packs`.
- manifest construction rejects EvidenceSet/OriginalityPack records from another ContentCase.
- manifest hashing is deterministic for the same bounded context.
- `ModelCall` start requires the exact ContextManifest and matching run, step, and prompt version.
- model completion rejects a result Artifact from another run or step.
- `ToolCall.request_fingerprint` includes both tool identity and normalized payload, so two different tools with the same payload do not collide.
- ModelCall/ToolCall success and failure telemetry preserves usage, latency, result refs, retry count, and normalized error class without adding a second budget counter.
- PR-B `load_budget_usage` reads the new ModelCall/ToolCall ledger rows directly.

```text
failed model/tool call
→ failed telemetry status
→ normalized error class preserved
→ no silent success
```
