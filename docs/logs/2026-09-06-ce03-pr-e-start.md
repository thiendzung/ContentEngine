## Contract gap found before implementation

`docs/05-HARNESS-SPEC.md` requires replay/eval mode, but `ContentRun.run_mode` in the current Data Contract/database only allows:

`create | update | refresh | localize`

PR-E resolves this explicitly by adding `eval` to the canonical `run_mode` contract and database constraint. Replay is the operation; `eval` is the persisted run mode.

This is a contract change and must be updated in `docs/03-DATA-CONTRACT.md` in the same PR before/with implementation.

## Architecture decisions

1. No new replay/eval table unless evidence shows one is required.
2. Immutable `Artifact` records hold the frozen replay fixture and eval report.
3. An eval run copies project/content-case/locale/content-item lineage from its baseline run but uses a candidate `SettingsSnapshot`.
4. The replay fixture records exact baseline run/artifact/context-manifest IDs and hashes.
5. Baseline run must be completed; referenced artifact and ContextManifest must belong to that baseline run.
6. Important external side effects are forbidden for `eval` runs at the durable outbox boundary.
7. Candidate model/tool execution reuses existing ModelRouter, ToolAdapter, ContextManifest and telemetry from PR-C.
8. Eval report compares persisted baseline vs candidate artifacts, quality evaluations and model/tool usage.
9. PR-E only reports differences. It does not activate/promote settings, prompts, recipes or models.
10. CE04 work is out of scope.

## Required synthetic gate

Prove one completed baseline run can be replayed as an eval run with frozen inputs/context, candidate settings/model/prompt, and a deterministic report, while any publish/outbox attempt is rejected and no configuration is auto-promoted.
