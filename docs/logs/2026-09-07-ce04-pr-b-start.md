## Architecture decisions

1. `knowledge` owns entity linking and retrieval.
2. Do not add vector infrastructure by default. PR-B must prove the smallest useful deterministic retrieval path first.
3. Entity linking baseline uses exact normalized canonical-name/alias matching against known project Entities.
4. Cross-project entity links are forbidden.
5. Ambiguous aliases that map to more than one Entity are not silently resolved; they are recorded as conflicts and skipped.
6. Derived chunk links are stored in existing `KnowledgeChunk.metadata_json` with an explicit linker version. No new table is required for this baseline.
7. Entity links are retrieval metadata only. They do not create Claim/Evidence and do not become factual authority by themselves.
8. Retrieval is project-scoped, optional locale-scoped, and reads only active chunks from the latest SourceDocument version for each Source.
9. Retrieval ranks relevance first, then explicit source metadata dimensions. It does not compute or expose a single fake authority score.
10. Search rank/position is never an authority input.
11. `authority_hint`, `commercial_bias`, source type preference and entity overlap remain separate ranking signals/reasons.
12. Unknown authority/bias values remain neutral rather than being promoted.
13. T04.9+ production provider routing/adapters and all Discovery/Evidence workflows are deferred.

## Proposed retrieval interface

Input:

- `project_id`;
- query text;
- optional locale;
- result limit;
- optional preferred source types;
- explicit authority/bias ordering policy.

Output per hit:

- chunk/document/source refs;
- matched query terms;
- matched entity refs;
- exact phrase flag;
- source type;
- `authority_hint`;
- `commercial_bias`;
- transparent ranking reasons/signals.

No single opaque total score is required.

## Failure modes to prove

- identical/ambiguous alias does not silently link to the wrong Entity;
- entity from another project is never linked/retrieved;
- stale superseded SourceDocument chunks are not returned;
- more relevant text beats a less relevant source merely because its authority hint is stronger;
- when relevance is equivalent, stronger explicit authority / lower commercial bias can break ties;
- `rank_position=1` metadata does not improve authority order;
- retrieval output is deterministic under the same persisted inputs/policy.

## Exit gate

Synthetic proof:

```text
known project Entities
→ exact alias/canonical-name link into active KnowledgeChunks
→ ambiguous alias skipped with explicit conflict
→ query
→ latest-document active chunks only
→ lexical/entity relevance
→ authority/type/bias tie-breaks
→ transparent reasons
→ deterministic result order
```

Full CI must pass before T04.6–T04.8 are checked.
