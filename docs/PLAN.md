## Release boundaries

Backend F5 completion is not proof of unattended operation. Agent-operated pilot additionally requires enforced operator/reviewer separation, bounded grant, durable continuation after human decisions, useful review UI and O1 deployment/recovery.

Assisted real production through already-reviewed services may produce value earlier, but requires a verified compatible path and explicit grant. Label it assisted; no SQL repair, one-off alternative engine or claim of no-human-technical-intervention proof.

O2 new Model Routing activation is optional if current approved routing suffices. Operational schema/configuration changes always require exact authorization and recovery proof. No automatic publish, merge, live-code self-repair or unsafe provider fallback.

## Improvement rule

Measure approved useful output, human edit effort, technical interventions, calls/time and failures. Reproduce in isolated TEST -> small fix -> regression -> MG review -> Founder merge/release -> observe again. Critical defects interrupt immediately; non-critical polish is ranked by observed burden, not platform ambition.

This replaces the UI-first and per-stage human-operator assumptions in earlier finish-first roadmaps, not their evidence/approval/security guarantees. Legacy phase history remains in Git and dated logs; no new workflow engine or phase renumbering.
